### 2026-05-05 — Wiring up `R/02_clean.R` for PORDATA, and two data-semantics bugs the LLM missed

**Prompt:** Open `pordata.xlsx`, write the cleaning logic, run the pipeline.

**Response (summary):** Claude inspected the PORDATA layout (5 metadata rows + a header row with year labels in cols 3–21 for the "Total" block, repeated for Masculino/Feminino at cols 22+/41+), wrote the wide-to-long pivot, and ran the full pipeline producing `flow_index.rds` and a `headline.csv`. It also caught and fixed: (a) `janitor` renders `Nº` as `no_`, not `n_`; (b) PORDATA in this dataset uses NUTS 2024, splitting Lisboa into three NUTS II units which all map to Região de Saúde LVT; (c) a Unicode NFC/NFD mismatch between SNS data (composed `ã`) and the crosswalk source file (decomposed `a` + combining tilde) causing silent join failures.

The first results table reported "SNS captures ~20 % of PORDATA's regional birth counts" and presented it as a structural finding requiring a major caveat in the discussion. **I noticed this couldn't be right** — PORDATA reports ~81,591 births for Portugal in 2014, not the ~423,000 the LLM was implicitly comparing to. Pushed back on the claim.

The actual bug: SNS monthly values are **cumulative year-to-date** within each year (Cascais 2013-01 = 206, 2013-02 = 383 = Jan+Feb, …, 2013-12 = 2,304 = annual total; 2014-01 = 191 resets the counter). Claude's pipeline was summing monthly values, producing 6× inflation per hospital and ~5× inflation nationally. After replacing `sum()` with `slice_max(date, n = 1)` to take the December value (or latest reported month), SNS 2014 totals dropped from 427k to 67,672 — approximately **86 % of PORDATA Continental**, not 20 %. The "coverage gap" went from catastrophic to moderate, and the project's central thesis became defensible again.

**Critical comment:** This is the most important entry in this log so far — and it's worth restating clearly: **the LLM produced a complete, internally-consistent, statistically rigorous analysis built on top of a silent data-semantics bug.** Every test passed, every figure rendered, the README looked clean, and the only reason the bug was caught is that I cross-checked one summary statistic against a PORDATA value I happened to remember (~81,591 births for 2014). The lessons:
1. **Always sanity-check national/aggregate totals against an external source you trust before believing any per-unit conclusions.** A bug like this is invisible at the per-hospital level — Cascais's 14,799 looks plausible if you don't know what to expect.
2. **Read the data dictionary or, failing that, eyeball a single entity across consecutive months.** Cumulative-YTD counters are a common pattern in administrative dashboards and the Transparência SNS schema doesn't flag it explicitly.
3. **Be sceptical of an LLM's "discovered limitation" when the numbers seem off** — Claude's first-pass interpretation was to attribute the 5× discrepancy to "structural under-coverage of SNS vs private hospitals", which sounded plausible enough that it almost survived. The real explanation was a one-line bug in `02_clean.R`. *Plausible-sounding causal narratives are exactly the kind of error LLMs are most prone to: fluent, coherent, and wrong.*
4. The corrected analysis (Moran's I = 0.458, p < 1e-4 for spatial clustering; flow ranking matches prior expectations) is now defensible and the policy argument holds.
